B9

In the UK, Ireland and Portugal two Games tab days merge into one on the spring clock change

lowconfirmededge
Impact

One of the two days has no chip, and its games cannot be reached from the Games tab. Happens one day a year, only in zones whose standard offset is UTC+0.

How it happens
  1. Set the phone to Europe/London (or Dublin, Lisbon).
  2. Open Games on the last Sunday of March (clocks go forward, a 23 hour day).
  3. Look at the day chips: Sunday matinee games and Sunday evening US games fall on Mar 29 and Mar 30 local days.
Where
StatScout/Models/Game.swift:236StatScout/Models/Game.swift:246
Suggested fix

Build the id from the calendar's own year, month and day components, not a GMT-formatted instant.

Evidence
static func key(_ date: Date) -> String {
    date.formatted(.iso8601.year().month().day())
}
...
let day = GameDay(date: day(of: game, calendar: calendar), phase: game.seasonPhase)
seen[day.id] = day

GameDay.id is built from key(date), and the iso8601 format style defaults to GMT, not the calendar's zone. London midnight on Mar 29 is 2026-03-29T00:00Z and London midnight on Mar 30 (BST) is 2026-03-29T23:00Z, so both keys are 2026-03-29. days(in:) stores them in a dictionary by id, so one overwrites the other.

Checked by: testP2_londonSpringForwardDaysCollapse_FAILS_IF_BUG failed as the bug predicts: GameDay.days returned one day, ids ["REG-2026-03-29"], for games on the London 29th and 30th ('1' is not equal to '2').

Where
