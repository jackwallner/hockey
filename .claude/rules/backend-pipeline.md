# Hockey StatScout: backend and data pipeline

The contract (sources, schema, metric catalog, qualification, season rules) is `project-docs/architecture/HOCKEY_CONTRACT.md`. This file records what is implemented. Only game details and enrichment still describe the football chassis in the code and are being converted (see the last section).

## Implemented: snapshots, history, career

- **Sources** (keyless, cloud-IP friendly): MoneyPuck season summary CSVs `https://moneypuck.com/moneypuck/playerData/seasonSummary/<season>/<regular|playoffs>/<skaters|goalies>.csv` (five situation rows per player: `all`, `5on5`, `5on4`, `4on5`, `other`; icetime in seconds) and the NHL stats REST `https://api.nhle.com/stats/rest/en/<skater|goalie>/summary` (`limit=100`, `start=`, `sort=playerId`, `cayenneExp=seasonId=<YYYY(YYYY+1)> and gameTypeId=<2|3>`) for +/-, PPG, PPP, SHG, GWG, W/L/OT, SO, GS and shooting hand. `SOURCE = "moneypuck"`. Requests carry the User-Agent `Hockey StatScout (jackwallner+bb@gmail.com)`, one GET per file, 0.3 s pause.
- **Headshots**: `image_url` = `https://assets.nhle.com/mugs/nhl/<seasonId>/<TEAM>/<playerId>.png` (200 only for the right team; a wrong team returns a 302). No landing-endpoint calls. The historical bundle strips `image_url`.
- **Caching**: finished seasons are cached in `backend/.cache/` (gitignored) keyed by URL and query; the live season never reads the cache. `HOCKEY_NO_CACHE=1` disables it. The backfill fills it and the career rollup reuses it.
- **Season rule**: label = start year (2026 = 2026-27), `season = year if month >= 9 else year - 1`; `STATCAST_SEASON` overrides; floor 2008. NHL `seasonId` = `f"{season}{season+1}"`. Career rollup is season `0`. `season_type` is `REG` or `POST`; preseason is ignored.
- **Tables**: `player_snapshots` PK `(id, season, season_type)`, `id` = NHL player id, `player_type` in `f` / `d` / `g`, `position` keeps the raw code (C, L, R, D, G), `handedness` = NHL `shootsCatches`. Metric id = `<category-slug>-<pid>-<mid>`. `player_game_logs`, `player_recent_form` and `games` are written by the modules below; `game_details`, `team_ratings` and `game_projections` exist in the schema but their writers are ported in a later pass.
- **Categories** (jsonb `metrics[].category`, exact strings): `Scoring` (f, d), `Shot Quality` (f, d), `Play Driving` (f, d), `Goaltending` (g). Formats include `sv3` (`.915`) and `dec3`. Percentiles are ranked inside the cohort (forwards vs forwards, defensemen vs defensemen, goalies vs goalies), inverted metrics rank lower raw values higher.
- **All rates come from summed counts** (never MoneyPuck's rounded percentage columns), so a season and the career rollup share one code path: `ingest.build_agg` over raw frames, then `ingest.build_snapshot_rows`.
- **Qualification** (one `QUAL_*` block at the top of `backend/ingest.py`): REG skaters `icetime >= 200 min` at `all` (Play Driving also `5on5 >= 150 min`), goalies `>= 600 min` or `>= 10 GP`; POST skaters 4 GP, goalies 2 GP; career skaters 300 GP, goalies 100 GP; career POST 50 / 25 GP (the contract is silent, these are our choice). Live season: bars scale by `qual_scale` = median club games / 82 (floor 0.1), every player with volume ships, each metric carries `qualified`. Finished seasons never scale, including the 2012-13 and 2019-20 short ones.
- **Supabase**: project ref `swlalptdamfccgjmpbyb` (football Supabase account, second free slot). Creds in `~/.hockey_credentials` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_DB_PASSWORD`, `SUPABASE_PROJECT_REF`). Apply SQL with `PGPASSWORD="$SUPABASE_DB_PASSWORD" psql "host=db.$SUPABASE_PROJECT_REF.supabase.co user=postgres dbname=postgres sslmode=require" -f <file>`; the Management API token does not reach this account. Migrations are applied in filename order; `20261008000000_hockey_schema.sql` adds the `player_profiles` columns (birthplace, toi_seconds, toi_per_gp, pp_toi_seconds, pk_toi_seconds, toi_share), `shots_status` / `summary_status` on `data_refresh_state` and `data_refresh_runs`, and re-creates `data_refresh_status` with them after the existing columns (`ngs_status` / `pfr_status` kept, left `unknown`). `20261008010000_hockey_refresh_status.sql` makes `update_data_refresh_build` (two new trailing params `p_shots_status`, `p_summary_status`; the old 11-arg overload is dropped) and `publish_data_refresh` write them, and publish as `degraded` when either is `pending` or `degraded`.
- **Python**: `python3 -m venv backend/.venv && backend/.venv/bin/pip install -r backend/requirements.txt`. Tests: `backend/.venv/bin/python -m pytest backend/tests/test_ingest.py backend/tests/test_rollup_all_time.py scripts/tests -q` (root `pytest.ini` puts `backend/` on the path; CI also sets `PYTHONPATH=backend`).
- **Backfill**: `source ~/.hockey_credentials && backend/.venv/bin/python scripts/backfill_historical.py` (2008 through the last complete season, REG and POST, then validates each season: row floor, no duplicate keys, team count by league size, f/d/g present, the four category strings only). `--validate-only` audits without ingesting. Then `backend/.venv/bin/python backend/ingest.py --season <live> --season-type all` and `backend/.venv/bin/python backend/rollup_all_time.py`.
- **Historical bundle**: `StatScout/Data/players-historical.plist` = seasons 2008..last complete plus the season-0 career rollup, regenerated with `source ~/.hockey_credentials && backend/.venv/bin/python scripts/export_historical.py --historical-only` (writes the JSON, then `swift scripts/convert_historical_to_plist.swift`). Past seasons are the only thing the bundle provides, so a season missing here is missing from the app. Always pass `--historical-only`; no current-season snapshot ships in the bundle. Ahead of a September rollover fold the outgoing season in early with `STATCAST_SEASON=<next>`.

## Implemented: games, game logs, recent form, probe, refresh

- **Games** (`sync_games.py`, stdlib only): `public.games` from the NHL schedule for the live and previous season. Full sync = `club-schedule-season/<TEAM>/<seasonId>` for 32 clubs (cheaper than walking `schedule/<date>`, about 37 weekly calls a season; every game appears under both clubs and is de-duplicated). The 15-minute score sync is one `schedule/<yesterday>` call (it returns seven days). `game_type` is `REG` or the playoff round read from the round digit of the id (`2025030186` -> `R1`). `week` counts 7-day blocks from the Monday on or before `regularSeasonStartDate`, which comes from `schedule/<season>-10-15`. `game_date` is the local date NHL files the game under (not the UTC date of `startTimeUTC`). Scores only when `gameState` is `FINAL` or `OFF`. The 2026-27 schedule has 84 games a club (1344 league games); `ingest.LEAGUE_GAMES` is still 82.
- **Game logs** (`ingest_game_logs.py`): one row per player per final game, `game_id` set, keys exactly the contract's. Sources per game: NHL boxscore (counts, TOI), NHL play-by-play (faceoff counts, primary assists, the shooter's blocked attempts; the boxscore has only a faceoff percentage) and the MoneyPuck shots zip (ixG, unblocked attempts, high-danger shots at xG >= 0.2, goalie xGA and HD against). `shot_attempts` = unblocked attempts + blocked ones, which reproduces MoneyPuck's season `I_F_shotAttempts`. Shot-file `game_id` is the NHL id without its first four digits (`2025020001` -> `20001`). A final is ingested only once the shot file contains it (else a false zero ixG); the rest wait for the next run. Incremental = finals in `games` with no goalie rows yet; `--full` re-ingests and prunes. About 1.3 s a game (two NHL calls, 0.3 s pause each), so a full season is roughly 35 minutes. Validated against MoneyPuck season totals: goals, takeaways, giveaways, primary assists exact; ixG within 0.5%; HD shots within 1 per player (MoneyPuck's own HD rule is not exactly xG >= 0.2).
- **Recent form** (`rollup_recent_form.py`): windows 2/4/8 weeks measured in days off the league anchor (latest `game_date` for the season and phase): current `(anchor - 7N, anchor]`, previous the equal block before. `start_week`/`end_week` are league weeks of the span's first day and of the anchor. Skater and goalie keys per contract; rates are recomputed from summed counts and zero denominators are omitted. `shooting_pct` is 0-100, `sv_pct` a fraction, matching the snapshot values. The recent-form rows keep the FK to `player_snapshots`, so logs of players without a snapshot are dropped from the rollup only.
- **Probe** (`source_probe.py`): HEAD (ETag, Last-Modified, Content-Length) on MoneyPuck `skaters.csv`, `goalies.csv`, `teams.csv` for regular and playoffs, and `shots_<season>.zip`. Required for readiness: regular skaters, goalies and shots; playoff and teams files are optional but fingerprinted, so a playoff file appearing starts a refresh. NHL endpoints are not fingerprinted. MoneyPuck regenerates daily even without games, so most daily refreshes end as `unchanged` via the content hash. The RPC contract (`record_data_refresh_probe`) is unchanged; the project host check is the hockey project.
- **Refresh** (`refresh.py`): snapshots rebuilt in full, game logs incremental, all under one refresh id. The publisher replaces a season's logs wholesale and rejects a revision that drops a game, so the candidate stages the published rows plus the newly built finals. `expected_games` = finals in `games` for the season, `observed_games` = finals with log rows; a final MoneyPuck has not published yet makes coverage `partial`, `shots_status` `pending` and the publish `degraded`. A shot-file download failure keeps the published logs and records `shots_status = degraded`. `summary_status` is the NHL stats summary status from `ingest.build_agg_for_season`. The content hash normalises whole-number floats so rows read back from Postgres hash like freshly built ones. `--full-logs` (workflow input `full_game_log_reingest`) rebuilds every final.
- **Planner** (`refresh_schedule.py`, stdlib only): probe every 30 minutes from a game's start + 2.5 h to + 12 h, hourly to + 36 h (also hourly up to 5 days for a final still missing its logs), else every 6 hours in October to June and daily July to September. Schedule: score sync every 15 minutes from 15 minutes before a game's start to + 4 h while it is not final, full sync once a day. The last full sync is read off the `synced_at` of games older than yesterday, because the score sync keeps the newest stamp fresh.
- **Workflows**: `nightly-statcast.yml` (display name "NHL Refresh", file name kept) = plan, probe, refresh, then the still-football game details and enrichment steps with `continue-on-error`; cron `7,37 * * 10-12,1-6 *` and `13 10 * 7-9 *` as the backup to the self-booked `refresh-timer.yml` chain; no test step (CI runs them). `enrichment.yml` runs `0 11 * 10-12,1-6 *`; its job body is the football script until the enrichment port. Repo secrets `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` exist.
- **Pruning** (`prune_history.py`): manual tool, keeps the two newest seasons of logs and recent form.
- **SQL fixtures**: `backend/tests/publisher_integration.sql` and `unchanged_integration.sql` run against a disposable Postgres with every migration applied (roles `anon`, `authenticated`, `service_role` and `pgcrypto` first). Run them after any change to the publish RPCs.
